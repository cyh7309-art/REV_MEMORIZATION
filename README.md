# 계시록 암송 트레이너

요한계시록(개역한글)을 **본문 읽기 → 선택 → 암송 → 입력 → 채점 → 오답 분석 → 재암송 → 기록 → 간격 반복 복습**의
학습 루프로 훈련하는 웹 앱입니다. 서버 없이 브라우저에서 바로 동작하며,
모든 학습 데이터는 사용자의 브라우저에만 저장됩니다.

타이핑과 **음성** 두 가지로 암송할 수 있고, 짧은 범위에서 시작해 한 장을 통째로 쌓아가는 **누적 암송**,
점수에 따라 복습 주기를 자동 조정하는 **간격 반복**, 여러 수강생의 백업을 모아 집계하는 **취합 보고서**,
오프라인 설치(**PWA**)를 지원합니다.

---

## 1. 실행 방법

### 가장 간단한 방법 — 더블클릭

```
index.html 을 더블클릭 → 브라우저에서 바로 실행
```

설치도, 빌드도, 서버도 필요 없습니다. `file://` 로 열어도 본문 데이터가 정상 로딩되도록
`data/revelation_kor.js`(내장 데이터)를 함께 넣어두었습니다.

### 로컬 서버로 실행 (선택)

`data/revelation_kor.json` 을 직접 교체하며 쓰거나, 나중에 PWA로 확장하려면 서버가 편합니다.

```bash
cd 계시록암송웹개발
python3 -m http.server 8080     # 또는  npx serve .
# 브라우저에서 http://localhost:8080 접속
```

### 휴대폰에서 쓰기 / 앱으로 설치 (PWA)

로컬 서버를 켠 뒤 같은 Wi-Fi의 휴대폰에서 `http://<PC IP>:8080` 으로 접속하고
Safari는 공유 → **홈 화면에 추가**, Android Chrome은 메뉴 → **앱 설치**를 누르면 앱처럼 설치됩니다.
설치 후에는 서비스워커가 앱과 본문 데이터를 캐시하므로 **인터넷 없이도 실행**됩니다.

> 서비스워커와 설치는 `https` 또는 `localhost` 에서만 동작합니다.
> `file://` 로 열어도 앱 기능은 모두 정상이며, 설치·오프라인 캐시만 빠집니다.
> 파일을 수정한 뒤 새 버전을 반영하려면 `sw.js` 의 `CACHE_VERSION` 값을 올리세요.

음성 암송도 마이크 권한 때문에 `https` 또는 `localhost` 를 권장합니다.

## 2. 기능 목록

### 본문 읽기 (암송 전 공부)
- 요한계시록 22장 404절을 장 단위로 읽는 화면
- `‹` `›` 버튼 · 장 선택 드롭다운 · 키보드 좌우 화살표로 장 이동
- **절을 눌러 범위 잡기** — 시작 절을 누르고, 종료 절을 한 번 더 누르면 범위가 확정됩니다.
  같은 절을 다시 누르면 해제, 범위가 잡힌 상태에서 누르면 새로 시작합니다.
  잡은 범위는 **"이 범위 암송하기"** 로 그대로 암송 화면에 이어집니다.
- **가리고 읽기** — 본문을 덮어두고 절을 하나씩 눌러 확인합니다. 눈으로 외운 뒤
  스스로 점검할 때 쓰는 기능으로, 채점 없이 가볍게 반복할 수 있습니다.
- **글자 크기** 3단계 (작게 · 보통 · 크게) — 설정에 저장되어 다음에도 유지됩니다.
- **절별 익힘 표시** — 학습 기록을 바탕으로 절 번호에 색이 붙습니다.
  90점 이상 받은 적이 있으면 초록(익힘), 시도했으나 미달이면 노랑(학습 중), 나머지는 회색.
- **장 진도 막대** — 그 장에서 익힌 절 수 / 전체 절 수 (익힘 절 기준 %)
- 홈의 "본문 먼저 읽기", 범위 선택·결과 화면의 "📖 본문 보기 / 본문 다시 읽기" 로도 들어올 수 있습니다.

### 범위 선택
- 장 / 시작 절 / 종료 절 자유 선택 (장을 바꾸면 절 목록이 자동 갱신)
- `시작 절 > 종료 절`, 범위 초과 등 잘못된 선택은 즉시 오류 안내
- "N장 전체" 버튼, 즐겨찾기·추천 범위 원클릭 선택
- 선택 즉시 절 수 / 글자 수 / 최근 점수 미리보기

### 암송
- 본문을 숨긴 상태로 입력 (채점 전에는 정답이 화면에 없음)
- 시작과 동시에 타이머 작동, 채점 시 정지
- 입력 글자 수 / 예상 본문 글자 수 실시간 표시
- 3단계 힌트
  1. 첫 자음(초성)만 — `예수 그리스도의` → `ㅇㅅ ㄱㄹㅅㄷㅇ`
  2. 각 어절의 첫 글자만 — `예_ 그____`
  3. 각 절의 앞 3어절 공개
- **음성 암송** — 🎤 버튼을 누르고 소리 내어 암송하면 인식된 문장이 입력창에 이어 붙습니다.
  타이핑과 섞어 써도 되고, 채점은 동일한 엔진을 씁니다.
  잠시 말을 멈춰 안드로이드가 인식을 끊더라도 **자동으로 다시 듣기를 이어갑니다.**
  (조용한 상태가 계속되면 스스로 종료합니다.)
- 키보드 단축키: `Ctrl/⌘+Enter` 채점, `Alt+H` 힌트, `Alt+V` 음성, `Esc` 뒤로

### 채점
- 어절 단위 diff (LCS) + 한글 자모 단위 유사도
- **절 번호를 적어도 감점되지 않습니다.** 시험지처럼 `1 예수 그리스도의 … 2 요한은 …` 으로
  절을 나눠 적어도 숫자는 본문이 아니라 절 번호로 봅니다.
  `1` `1.` `1)` `(1)` `[1]` `1:` `1절` `제1절` `20:1` 전각 숫자 모두 인식합니다.
  (설정에서 "절 번호도 본문처럼 채점"을 켜면 예전처럼 숫자도 셉니다)
- 정확 / 비슷함 / 틀림 / 빠뜨림 / 잘못 넣음 / **순서 바뀜** 6분류 시각화
- **어절 순서만 바꿔 쓴 경우**는 한 번의 실수로 봅니다. 예전에는 원래 자리에서 `빠뜨림`,
  엉뚱한 자리에서 `잘못 넣음` 으로 **두 번 깎였습니다.** 말 자체는 알고 있었으므로 그만큼 인정합니다
- **한 낱말을 둘로 나눠 쓴 경우**(`증거하였느니라` → `증거 하였느니라`)도 붙여 쓴 경우처럼
  띄어쓰기로 봅니다. 같은 자리에 다른 실수가 섞여 있어도 잡아냅니다
- **윗줄은 정답 본문, 아랫줄 작은 글씨는 내가 쓴 말** — 클릭하지 않아도 무엇을 틀렸는지 보입니다
- **취소선은 "빼면 되는 말"에만** 붙습니다 (본문에 없는데 넣은 말).
  빠뜨린 말은 점선 테두리로 "비워 둔 자리"처럼 보여줍니다
- **이번에 자주 나온 실수** — 띄어쓰기 / 조사·어미 / 오타 / 빠뜨림 / 잘못 넣음 / 다른 표현으로
  유형을 세어 많은 순으로 보여줍니다. 개수보다 "어떤 식으로 틀렸는지"가 다음 암송에 도움이 됩니다
- **틀린 절만 보기** — 긴 범위에서 맞은 절을 접고 문제되는 절만 봅니다
- **지난번과 비교** — 같은 범위를 다시 암송하면 직전 점수와 나란히 보여주고,
  `고쳐진 절` / `계속 약한 절` / `이번에 약해진 절` 을 짚어줍니다. 몇 번째 시도인지도 함께 표시합니다
  (오답만 연습한 기록은 범위가 다르므로 비교에서 빠집니다)
- 어절을 클릭하면 정답·내가 쓴 말·유사도·진단을 팝업으로 표시
- 절별 점수와 막대그래프, 80점 미만 절은 "이 절만 다시" 버튼
- **오답만 연습** — 80점 미만 절만 모아 즉시 재암송
- 점수대별 격려 문구

### 즐겨찾기
- 범위 추가 / 삭제 / 중복 방지, `localStorage` 저장 (새로고침 후 유지)
- 즐겨찾기 항목을 누르면 바로 암송 화면으로 이동
- 범위별 시도 횟수·평균·최고 점수 함께 표시

### 학습 기록 · 통계
- 점수, 정확도, 소요 시간, 힌트 사용, 날짜 저장 (최근 500회)
- 총 암송 횟수 / 평균 / 최고 / 최근 점수 / 총 학습 시간 / 연속 학습일
- 최근 12회 점수 추이 그래프, 자주 틀리는 절, 보완이 필요한 범위
- 성취 8종 (첫 암송, 10회, 100회, 90점, 100점, 7일·30일 연속, 10개 범위)

### 간격 반복 복습 (SM-2)
채점할 때마다 점수를 응답 품질(0~5)로 바꿔 다음 복습일을 자동 계산합니다.

- 잘 외운 범위는 1일 → 4일 → 10일 → 24일 … 로 간격이 벌어지고,
  80점 미만이면 다시 다음날로 돌아옵니다
- 홈 화면에 **오늘 복습할 범위**가 밀린 순서대로 뜹니다
- 학습 기록 화면에서 앞으로의 일정과 범위별 난이도 계수를 볼 수 있습니다
- 오답만 연습(부분 범위)은 일정에 반영하지 않습니다

### 누적 암송
짧은 범위부터 시작해 통과할 때마다 뒤로 넓혀 한 장을 통째로 쌓는 방식입니다.

```
계 1:1~4  →(90점 이상)→  1:1~8  →  1:1~12  →  …  →  1:1~20 (완주)
```

- 범위 선택 화면에서 **이 범위로 누적 암송 시작**
- 90점 이상이면 결과 화면·홈에 **확장** 버튼이 나타나고, 누르면 넓힌 범위로 바로 암송이 시작됩니다
- 장의 마지막 절을 넘지 않으며, 홈에서 진행률(예: `2장 8/29절`)을 확인할 수 있습니다

### 여러 명 학습 현황 취합 (인솔자용)
수강생이 [설정 → 백업 파일 내려받기]로 만든 JSON을 여러 개 한꺼번에 선택하면 집계합니다.

- 전체: 참여 인원, 총 암송 횟수, 평균 점수, 오늘 학습 인원, 7일 이상 미학습 인원
- 인원별: 횟수 / 평균 / 최고 / 연속 학습일 / 범위 수 / 학습 시간 / 최근 학습일
- 범위별: 참여 인원, 시도 횟수, 평균·최고·최저, 90점 이상 비율 (평균 낮은 순)
- 공통으로 자주 틀리는 절 — 여러 사람이 함께 틀리는 지점 = 교육 자료를 보완할 지점
- **CSV 내보내기** (엑셀에서 바로 열리도록 BOM 포함)

파일은 브라우저 안에서만 읽고 어디에도 전송하지 않으며, 집계 결과는 저장되지 않습니다.

### 오늘의 암송
1순위 복습이 필요한 범위 → 2순위 즐겨찾기 → 3순위 기본 추천 목록.
오늘 이미 암송한 범위는 뒤로 미뤄 같은 범위가 반복되지 않게 합니다.

### 설정
- 학습자 이름 (백업·취합 보고서에 표시)
- 힌트 감점, 문장부호 엄격 채점, **절 번호도 본문처럼 채점**, 간격 반복 사용,
  음성 버튼 표시, 타이머 표시, 자동 포커스
- 본문 JSON 불러오기 / 기본 본문으로 되돌리기
- 학습 데이터 백업 내려받기 · 복원 · 초기화 (복습 일정 · 누적 계획 개별 초기화 포함)
- PWA 설치 안내 및 설치 버튼

## 3. 파일 구조

```
계시록암송웹개발/
├── index.html                  화면 뼈대 (SPA)
├── manifest.json               PWA 설치 정보
├── sw.js                       서비스워커 (오프라인 캐시)
├── css/
│   └── style.css               전체 스타일 · 반응형
├── js/
│   ├── data.js                 본문 데이터 접근 · 범위 검증 · getPassage()
│   ├── storage.js              localStorage 격리 계층
│   ├── diff.js                 정규화 · 토큰화 · 자모 유사도 · LCS diff
│   ├── scorer.js               점수 계산 · 절별 집계
│   ├── statistics.js           통계 · 연속 학습일 · 성취 · 오늘의 암송
│   ├── srs.js                  간격 반복 복습 스케줄러 (SM-2)
│   ├── plan.js                 누적 암송 계획
│   ├── read.js                 본문 읽기 — 절별 익힘 상태 · 범위 선택 규칙
│   ├── voice.js                음성 인식 래퍼 (Web Speech API)
│   ├── report.js               여러 명 취합 · CSV 생성
│   ├── ui.js                   화면 렌더링 (HTML 생성, XSS 이스케이프)
│   └── app.js                  상태 · 라우팅 · 이벤트 · 타이머 · PWA 등록
├── data/
│   ├── revelation_kor.json     본문 데이터 (원본 · 교체용)
│   └── revelation_kor.js       같은 내용의 JS 버전 (file:// 실행용)
├── icons/                      PWA 아이콘 (192 · 512 · maskable · apple-touch)
├── tests/
│   ├── run-tests.js            로직 자동 검증 (node)
│   └── browser-check.js        브라우저 실동작 점검 (playwright, 개발용)
└── README.md
```

각 파일은 하나의 책임만 갖습니다. UI를 React로 옮기더라도
`data / storage / diff / scorer / statistics / srs / plan / read / voice / report` 열 개는 그대로 재사용할 수 있습니다.

의존 방향은 한쪽으로만 흐릅니다.

```
data ─┐
      ├─→ scorer ─┐
diff ─┘           │
                  ├─→ ui ─→ app
statistics ─→ srs │
            └→ plan
read ─────────────┤   (history → 절별 익힘 상태)
voice ────────────┤
report ───────────┘
storage  (srs · plan · read · report 가 저장에 쓰는 유일한 통로)
```

## 4. 본문 데이터

### 수록 내용

| 항목 | 값 |
|---|---|
| 성경 | 요한계시록 |
| 역본 | 개역한글 (성경전서 개역한글판, 1961) |
| 분량 | 22장 404절 (전 장 수록) |
| 인코딩 | UTF-8, 유니코드 NFC 정규화 |

장별 절 수는 실제 요한계시록 구조(1장 20절 … 22장 21절)와 일치하며, 앱 실행 시 자동 검증합니다.
불일치가 있으면 헤더에 **본문 미완성** 배지가 뜨고 설정 화면에 어떤 장이 문제인지 표시됩니다.

### 저작권 / 이용 조건

## 5. 채점 알고리즘

### 1단계 · 정규화

```js
text.normalize("NFC").replace(/\s+/g, " ").trim()
```

줄바꿈·탭·연속 공백 차이는 채점에 영향을 주지 않습니다.
문장부호(`.,!?“”‘’()` 등)는 기본적으로 무시하며, 설정에서 엄격 모드로 바꿀 수 있습니다.
화면에 보여주는 정답 본문은 원래 형태를 그대로 유지합니다.

### 2단계 · 어절 토큰화

띄어쓰기 기준으로 어절을 나눕니다. 표시용 원문(`raw`)과 비교용 키(`key`)를 분리해 두어,
비교는 관대하게 하면서 화면에는 원문 그대로 보여줍니다.

### 3단계 · LCS 정렬

정답 토큰 배열과 입력 토큰 배열의 최장 공통 부분 수열을 구해
`일치 / 정답에만 있음 / 입력에만 있음` 블록으로 나눕니다.
앞뒤로 동일한 구간은 DP 없이 건너뛰어 긴 범위도 빠르게 처리합니다.

### 4단계 · 블록 내부 짝짓기

`정답에만 있음` + `입력에만 있음` 이 붙어 있는 구간은 다음 순서로 해석합니다.

1. **띄어쓰기 오류 판정** — 두 구간을 붙였을 때 같은 문자열이면(`될 일을` ↔ `될일을`)
   내용은 맞고 어절 구분만 틀린 것으로 본다
2. **유사도 기반 정렬** — Needleman-Wunsch로 가장 그럴듯한 짝을 찾는다
3. 짝을 찾지 못한 정답 어절은 **누락**, 입력 어절은 **추가**

### 5단계 · 유사도 (한글 자모 단위)

글자 단위 편집거리는 한국어에 너무 가혹합니다(`속히`↔`속이` = 0.5).
그래서 한글 음절을 초성·중성·종성으로 분해한 뒤 레벤슈타인 거리를 계산합니다.

| 비교 | 글자 단위 | 자모 단위 | 판정 |
|---|---|---|---|
| 속히 / 속이 | 0.50 | **0.83** | 유사 (오타) |
| 하나님 / 하나님이 | 0.75 | **0.78** | 유사 (조사 차이) |
| 속히 / 사랑 | 0.00 | **0.33** | 오답 |

임계값은 `js/diff.js` 의 `CONFIG` 상수로 분리되어 있습니다.

```js
SIMILAR_MIN: 0.60   // 이상이면 유사, 미만이면 오답
NEAR_EXACT : 0.85   // 이상이면 "오타로 보입니다" 진단
```

### 6단계 · 점수 (`js/scorer.js`의 `WEIGHTS`)

| 구분 | 가중치 |
|---|---|
| 정확 | 1.0 |
| 유사 | 0.5 |
| 띄어쓰기만 다름 | 0.9 |
| 오답 | 0 |
| 누락 | 0 |
| 추가 입력 | −0.2 |

```
점수 = (가중치 합계 / 정답 어절 수) × 100 − 힌트 감점
```

힌트는 한 단계당 3점, 최대 10점까지 감점하며 설정에서 끌 수 있습니다.
최종 점수는 0~100으로 제한됩니다. 절별 점수도 같은 방식으로 계산합니다.

## 5-1. 간격 반복 계산 (`js/srs.js`)

점수를 SM-2 의 응답 품질로 환산한 뒤 복습 간격과 난이도 계수를 갱신합니다.

| 점수 | 품질 | 판정 |
|---|---|---|
| 95 이상 | 5 | 완벽 |
| 90~94 | 4 | 아주 좋음 |
| 80~89 | 3 | 통과 |
| 70~79 | 2 | 실패 |
| 60~69 | 1 | 실패 |
| 60 미만 | 0 | 완전 실패 |

```
통과(품질 3 이상)
  1회차 → 1일 뒤
  2회차 → 4일 뒤
  3회차 이후 → 직전 간격 × 난이도 계수

실패(품질 3 미만)
  연속 통과 횟수를 0으로 되돌리고 1일 뒤로

난이도 계수 = 계수 + (0.1 − (5−q) × (0.08 + (5−q) × 0.02))   (하한 1.3)
간격 상한 180일
```

상수는 `js/srs.js` 의 `CONFIG` 에 모여 있어 훈련 강도에 맞게 조정할 수 있습니다.

## 5-2. 음성 인식 결과 조립 (`js/voice.js`)

브라우저마다 인식 결과를 주는 방식이 달라, 순진하게 "받은 것을 뒤에 이어 붙이면"
안드로이드(갤럭시)에서 같은 구절이 눈덩이처럼 불어나는 문제가 생깁니다.

```
갤럭시 크롬의 실제 동작
  1번째 onresult → resultIndex 0, results = [또 내가]
  2번째 onresult → resultIndex 0, results = [또 내가, 몸에]          ← 앞의 것을 다시 보냄
  3번째 onresult → resultIndex 0, results = [또 내가, 몸에, 천사가]   ← 또 다시 보냄

이어 붙이기 방식의 결과
  "또 내가 / 또 내가 몸에 / 또 내가 몸에 천사가 …"   ← 중복 누적
```

그래서 이 앱은 **이어 붙이지 않고, 결과 인덱스를 키로 덮어쓴 뒤 매번 처음부터 다시 조립**합니다.

```js
absorbResults(store, results)   // store[i] = {text, final}  ← 같은 i 는 덮어쓰기
composeText(baseText, store)    // 인덱스 순서대로 다시 이어 붙여 문장 완성
```

같은 결과가 몇 번을 다시 들어와도 결과가 변하지 않으므로(멱등) 중복이 생기지 않으며,
서로 다른 인덱스의 결과는 그대로 보존되어 `또 내가 보매` 처럼 **실제로 반복되는 어구는 손실 없이 남습니다.**

안드로이드는 잠깐만 조용해도 인식을 끝내버리므로, 사용자가 끄지 않았다면 지금까지 확정된
내용을 이어받아 자동으로 다시 듣습니다. 조용한 상태가 연달아 `MAX_EMPTY_RESTARTS`(3)회
이어지면 스스로 종료하고, 마이크 거부·네트워크 오류처럼 회복이 불가능한 경우에는 재개하지 않습니다.

## 5-3. 채점 결과를 읽는 법

세로 한 칸이 어절 하나입니다. **윗줄은 언제나 정답 본문, 아랫줄 작은 글씨는 내가 쓴 말**입니다.
그래서 틀린 자리에서도 본문을 눈으로 이어 읽을 수 있습니다.

| 표시 | 뜻 | 어떻게 보이나 |
|---|---|---|
| 정확 | 맞음 | 초록 |
| 비슷함 | 조사·어미나 글자 하나가 다름 | 노랑 + 아랫줄에 내가 쓴 말 |
| 틀림 | 다른 말을 씀 | 빨강 물결 밑줄 + 아랫줄에 내가 쓴 말 |
| 빠뜨림 | 본문에 있는데 **안 씀** | 점선 테두리(비워 둔 자리), 아랫줄 `안 씀` |
| 잘못 넣음 | 본문에 없는데 **넣음** | **취소선**, 아랫줄 `뺄 말` |
| 순서 바뀜 | 말은 맞는데 **자리가 다름** | 보라색. 본문 자리는 `자리 바뀜`, 쓴 자리는 `여기 아님`(취소선) |

취소선은 "빼면 되는 말"에만 붙입니다. 빠뜨린 말은 지울 대상이 아니라 채워 넣어야 할 자리이므로
취소선을 쓰지 않습니다. (예전에는 이 둘이 반대로 되어 있어 혼동을 주었습니다.)

### 정렬 뒤 다듬기 (`js/diff.js`)

LCS 로 어절을 맞춰본 뒤, 사람이 보기에 억울한 판정을 두 단계로 되돌립니다.

```
mergeSpacingOps()  이어진 2~4개 어절을 묶어 붙여 읽어 본다.
                   양쪽 글자가 같은데 어절 수만 다르면 → 띄어쓰기 (감점 0.9)
                   ("증거하였느니라" ↔ "증거" + "하였느니라")

markMovedOps()     빠뜨린 말과 똑같은 말을 10어절 안에서 잘못 넣은 자리에 찾는다.
                   찾으면 → 순서 바뀜 (본문 자리 0.8, 쓴 자리 0)
                   예전: 빠뜨림 0 + 잘못 넣음 −0.2 = 한 실수에 두 번 감점
```

두 단계 모두 **정렬 결과를 고치는 것이 아니라 판정만 완화**하므로, 진짜 빠뜨림이나
진짜 군말은 그대로 잡힙니다. (테스트로 고정되어 있습니다)

- **순서 바뀜**: 이웃·원거리 전치 인식, 이중 감점 방지, 너무 먼 경우는 제외,
  진짜 빠뜨림·군말을 순서 바뀜으로 오인하지 않음
- **나눠 쓰기**: 다른 실수가 섞인 자리에서도 띄어쓰기로 인식, 붙여 쓰기 기존 동작 유지
- **지난 시도 비교**: 직전 기록 찾기, 점수 증감, 고쳐진·계속 약한·새로 약해진 절 구분,
  부분 범위 연습 제외, 자기 자신 제외
- **음성**: 미지원 환경에서의 안전한 실패, 문장 잇기,
  **안드로이드 중복 입력 방지**(결과 인덱스 기준 재조립·멱등성), 자동 재개·종료·마이크 거부 처리
- **취합**: 인원·범위·절별 집계, 깨진 파일 건너뛰기, CSV 이스케이프/BOM/CRLF
- **통합 시나리오**: 채점 → 복습 일정 → 누적 확장이 실제 본문 범위로 이어지는지

브라우저 실동작 점검(선택, playwright 필요):

## 8. 접근성 · 보안

- 색상만으로 구분하지 않습니다 — 각 어절에 기호(`≈ ✕ ⊘ +`)와 `aria-label`을 함께 붙입니다
- 모든 조작은 키보드로 가능하며 `focus-visible` 윤곽선을 표시합니다
- 본문으로 건너뛰기 링크, 버튼 `aria-label`, `aria-current`, `aria-live` 안내 제공
- `prefers-reduced-motion` 존중
- 사용자 입력은 항상 `escapeHtml()` 을 거쳐 DOM에 넣습니다 (XSS 방지). `eval` 미사용
- 불러온 백업·본문 JSON도 그대로 신뢰하지 않고 형식을 검사한 뒤 사용합니다
- 외부 라이브러리·CDN·네트워크 요청이 전혀 없습니다. 모든 데이터는 기기 안에만 있습니다
- 서비스워커는 같은 출처(origin)의 GET 요청만 캐시하며 외부로 아무것도 보내지 않습니다
- 음성 인식은 브라우저 기본 엔진을 사용하며, 앱이 음성을 저장하거나 전송하지 않습니다
  (Chrome 등 일부 브라우저는 인식 처리를 자체 서버에서 수행합니다)

## 9. 향후 확장 계획

| 단계 | 내용 |
|---|---|
| 클라우드 동기화 | `storage.js` 의 함수 시그니처를 유지한 채 Supabase·Firebase 어댑터로 교체. 취합도 파일 업로드 대신 자동 수집으로 |
| 절 단위 간격 반복 | 지금은 범위 단위. `weakVerses` 를 절 카드로 쪼개면 취약 절만 집중 복습 가능 |
| 다른 성경 | `data/*.json` 을 여러 권으로 늘리고 `data.js` 에 책 선택만 추가 |
| 음성 채점 튜닝 | 음성 인식 결과는 띄어쓰기·문장부호가 불안정하므로, 음성 입력 전용 관대 모드 추가 |
| 취합 자동 리포트 | 주간 단위로 CSV를 만들어 부서 보고 형식(요약 문구 포함)까지 자동 생성 |
